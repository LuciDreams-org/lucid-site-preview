Xero Integration Troubleshooting Checklist for Medical Practices

November 4, 2026 · 10 min read

A broken accounting connection can leave a private medical practice with missing payer receipts, incomplete payroll entries or unreliable location-level reports. But a connection that appears successful can also import only part of a batch. Restoring the connection and proving the accounting is complete are separate tasks.

This checklist is for owners and managers of staffed U.S. private practices already using Xero with a connected service. It helps you identify the affected records, gather useful evidence and coordinate a controlled repair with your bookkeeper and integration provider. It is not an API engineering guide or a recommendation for a particular connector.

Use this sequence:

  1. Confirm the connection, entity and affected period.
  2. Check authorization and permissions.
  3. Review available sync messages and item-level results.
  4. Inspect account mappings and compare source totals.
  5. Check for duplicates before approving a rerun.
  6. Reconcile the repaired period and document the outcome.

Until the scope is clear, avoid repeated reconnects, overlapping manual imports or broad historical reruns. Assign one person to coordinate changes so different team members do not attempt competing repairs.

1. Confirm the Affected Connection and Period

Start by describing what is missing or incorrect—not simply that “Xero is broken.” A bank feed, an app sending entries into Xero and a reporting service reading from Xero are different connections. A problem in one does not establish that the others have failed.

Record the source, destination and direction of the affected flow. Then confirm the Xero organization and legal entity involved. A practice with multiple entities should not assume that a connection working for one entity is also working for another.

Scope check What to record Practice-specific reason
Connection Source service, destination and direction Distinguishes missing accounting entries from a stale reporting export
Organization and entity Exact organization and entity names in an internal record Prevents investigating or repairing the wrong books
Location Affected site or all locations Helps isolate location coding from a broader connection failure
Record type Receipts, fees, payroll journals, bills or another category Defines which source records must be compared
Affected period First suspected missing date, last successful transfer and review end date Establishes a bounded investigation window
Financial impact Reports or close tasks that depend on these records Helps the owner decide what reporting must remain provisional

Check any available service notices from the provider before changing settings. If a disruption is reported, preserve the evidence and ask the provider how to handle queued records once service resumes.

Also note recent changes: a staff departure, access update, new account, new location or revised mapping. These are investigation leads, not proof of the cause.

2. Check Authorization and Permissions Without Sharing Credentials

Confirm that an authorized person can access the intended organization and that the connection is still associated with the correct organization. Review the authorization or permission messages available through the connected service.

Keep these questions separate:

  • Authorization: Is the connection authorized to communicate with Xero?
  • Permissions: Does it have permission to perform the affected operation?
  • Scope: Is it connected to the intended organization and records?

Do not assume that a manager's ability to sign in means the connected service has the access it needs. Conversely, an individual employee's access problem does not prove that the integration has stopped.

If access needs to be renewed, have the authorized administrator follow the provider's current instructions. Before disconnecting anything, ask whether that action affects queued records, saved mappings or the starting point for a subsequent transfer.

Never include passwords, access tokens, client secrets or full bank credentials in a support request. The practice manager's role is to coordinate authorized access—not to troubleshoot secret credentials through email or chat.

3. Review Sync Messages, Including Partial Failures

Save the exact message, timestamp with time zone, affected batch reference and last successful transfer time. Where available, record attempted, accepted and rejected item counts.

For connections using Xero's Accounting API, the official Xero response-code documentation provides the following limited guidance. These codes should not be assumed to describe every bank-feed or third-party service message.

Response Documented meaning Manager's next step
400 Validation problem Capture the validation message and affected item details for the provider
401 Authorization issue Ask the authorized administrator and provider to review authorization
403 Permissions issue Confirm the intended organization and ask the provider which permission is needed
429 Rate limit reached Give the provider the response and timing; avoid repeated manual reruns
503 Temporary API or organization unavailability Record the time and ask the provider when and how to retry

A successful overall response does not always prove that every item succeeded. Xero documents that, with summarizeErrors=false, an HTTP 200 response can accompany individual item failures. If the provider exposes item-level results, review them. Otherwise, ask support to confirm which records were accepted and which failed.

Avoid interpreting an unexplained error as a reason to change account mappings or import data manually. First establish whether the issue concerns access, availability, validation or incomplete processing.

4. Inspect Mappings and Compare Like-for-Like Totals

A working connection can still deliver incorrect accounting if records go to the wrong account, entity or location. Ask your bookkeeper to review the configured mappings against the practice's accounting treatment. Available mapping fields depend on the connected service; do not assume every connector supports location details or transaction-level transfers.

Data flow Mapping or comparison to inspect Potential reporting problem
Payer and patient receipts Gross receipts, adjustments, refunds, fees and net deposits Net deposits mistaken for gross collections
Provider and administrative payroll Wage expense, employer costs, liabilities and cash movement Payroll expense confused with the payroll bank withdrawal
Location activity Location coding, where supported Correct practice-wide totals but incorrect per-location P&L
Shared costs Existing allocation method and affected accounts Central expenses omitted from, or counted twice in, location reports
Entity-level transactions Destination organization and entity accounts Activity recorded in the wrong entity

Next, compare source records with the accounting entries for the same period. Establish whether the date means transaction date, posting date, settlement date or transfer date. Match report basis and filters before treating a difference as missing data.

Use both counts and amounts where meaningful. A summary entry may represent many source transactions, so equal record counts are not always expected. Compare the accounting components as well as the net total: two errors can offset each other.

Illustrative Example: A Receipt Batch That Appears Incomplete

Suppose a practice's source settlement report shows $24,000 in receipts, $600 in processing fees and a $23,400 net deposit. These are illustrative figures, not a practice benchmark.

A $23,400 bank deposit does not by itself establish that receipt entries are missing. First determine whether the approved accounting treatment records gross receipts and fees separately or uses a clearing account. Compare the source settlement, imported entries and resulting balances using that treatment.

If fees are absent or the receipt entry is duplicated, the bookkeeper can identify the specific correction. A broad rerun before that review could make an initially understandable difference harder to resolve.

5. Complete a Duplicate Check Before Any Rerun

A failed batch may contain records that already reached Xero. An interrupted transfer also may leave uncertainty about what was accepted. Do not treat “failed” as equivalent to “nothing imported.”

Before approving a retry, complete this checklist:

  • Identify the exact date range and record types proposed for reprocessing.
  • Search existing accounting records for source references, dates and amounts.
  • Identify partial batches and entries created during earlier retry attempts.
  • Check for manual entries or imports made while the connection was unavailable.
  • Ask the provider whether replaying the affected records creates new entries, updates existing entries or follows another documented behavior.
  • Agree which person will authorize the action and which person will verify the result.

A narrow rerun is appropriate only when the provider confirms it is supported and its treatment of existing records is understood. Do not assume a full resync, reconnect or targeted retry is duplicate-safe.

If the practice needs interim reporting, have the bookkeeper document any temporary entries and the plan to review them after restoration. Do not add a manual import on top of an uncertain automated queue without an agreed reconciliation plan.

Corrections affecting a closed period, payroll liabilities or entity balances should go to the responsible accountant before changes are made.

6. Reconcile After the Repair

The repair is not complete when the connection turns green. Verify that the affected period is complete, correctly classified and free of unexplained duplication.

Post-repair check Evidence to retain
Completeness Source totals compared with imported totals; explanation for any count differences
Rejected items Item-level results or provider confirmation of remaining failures
Duplicates Review of overlapping transfers, manual entries and repeated source references
Classification Sample checks of accounts, entity and location coding
Cash and clearing balances Relevant settlement or bank comparisons and explanations for timing differences
Reports Updated P&L and balance-sheet review for the affected entity and period
Ongoing operation Evidence that a subsequent scheduled transfer completed as expected

Keep unresolved differences visible. For each one, record the amount, explanation, owner and next action. A known settlement timing difference is different from an unexplained missing batch.

The IRS's business recordkeeping guidance in Publication 583 supports maintaining complete records and reconciling bank records. The integration review complements those controls; it does not replace them.

Release affected management reports only after the bookkeeper or finance lead has reviewed the repair. If a difference remains, label the affected reports provisional and explain which decisions depend on resolving it.

Support Handoff Template: Use Sanitized Information

Send the integration provider a concise incident summary rather than a collection of unfiltered screenshots. Use the provider's approved support process for any additional sensitive details.

Field Information to provide
Issue summary Missing, duplicated, rejected or misclassified records
Connection Source, destination, direction and connection name
Organization reference Sanitized entity label; provide required identifiers through the approved support process
Timing Affected date range, time zone and last successful transfer
Error evidence Exact code, sanitized message, timestamp and batch reference
Financial comparison Aggregate expected and imported amounts, counts where meaningful, and difference
Existing entries Whether a partial batch or manual workaround already exists
Actions taken Access reviews, mapping changes and retry attempts, with times
Requested confirmation Which items succeeded, cause of failure, proposed repair and duplicate handling
Approval Practice contact authorizing changes and accountant reviewing the result

Remove patient names, dates of birth, medical record numbers, claim-level identifiers and clinical details from ordinary support summaries. Payroll evidence should also exclude unnecessary employee details. A screenshot can expose sensitive information outside the error message, so review the whole image.

HHS describes the minimum necessary standard and its exceptions. As a practical workflow, begin with aggregate financial evidence and sanitized references. Do not put patient-identifiable information into ordinary Slack messages or general-purpose AI tools.

Keep the Connection Review Part of Close

Assign a practice-side owner to check the last successful transfer, unresolved errors and source-to-accounting totals before close. Keep a short connection register showing the organization, source service, responsible administrator and accounting reviewer.

FAQs

Should we reconnect the app as soon as a sync fails?

Not automatically. First save the error, identify the affected period and check whether any records already arrived. Ask the provider whether reconnecting changes queued work, mappings or the transfer starting point. Restore access through the authorized administrator when that is the confirmed issue.

What if the sync says successful but some entries are missing?

Compare source totals with imported totals and request item-level results. Xero's response-code documentation notes that HTTP 200 can accompany individual failures when summarizeErrors=false. A success label alone is not enough to close the incident.

Can we manually import the missing records while waiting for support?

Only after the bookkeeper and provider establish what already posted and what may still transfer. Otherwise, manual entries can overlap with a later retry. Document any approved workaround and include it in the post-repair duplicate check.

Why do totals match overall but not by location?

The connection may have transferred the correct amounts without the expected location coding, or reports may use different filters or shared-cost allocations. Compare the same period and accounting basis, then inspect location assignments and the existing allocation method. A practice-wide total does not prove each location's P&L is correct.
